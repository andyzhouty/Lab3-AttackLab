## 5. Q3：找到输入缓冲区，观察字符串的真实字节

**先理解：** 本平台的整数或指针参数通常依次通过 `rdi`、`rsi` 等寄存器传递。`gets` 的第一个参数是接收输入的地址。因此要看它写到哪里，应在调用前查看 `rdi`。调用完成后，参数寄存器的值不保证保留，先把地址保存到 GDB 的便利变量中。

下面的偏移来自你在 Q1 记录的反汇编；若二进制改变，要重新核对。每项练习使用新的 GDB 会话最容易避免旧断点干扰；同一会话里可先用 `delete` 删除旧断点。

```gdb
break *input+35
run
x/i $pc
p/x $rdi
p/x $rbp-0x10
set $buf = $rdi
x/16xb $buf
ni
```

执行 `ni` 后，程序等待输入时，输入短表达式 `1+2` 并回车。等 `(gdb)` 提示符回来，再输入：

```gdb
x/i $pc
x/s $buf
x/16xb $buf
```

`set $buf = $rdi` 让 GDB 记下当时的地址。`x/16xb` 从该地址起按十六进制显示 16 个单字节；`x/s` 按以零字节结束的字符串显示内容。读取前的局部数组未初始化，原有字节不能当作程序承诺的初始值。

**填写：**

| 观察项              | 结果                      |
| ------------------- | ------------------------- |
| 调用前 `rdi` 的值 | 0x721000800fd0            |
| `rbp-0x10` 的值   | 0x721000800fd0            |
| 输入后的前几个字节  | 0x31    0x2b    0x32 0x00 |
| `x/s` 显示        | "1+2"                     |

1. 两个地址是否一致？这如何支持缓冲区位置的判断？
2. `1+2` 的三个字符后面是什么字节？换行符是否被保存在这里？
3. 数组容量、输入字符数、写入字节数有什么区别？本次分别是多少？

**我的回答：**

1. 两个地址一致。反汇编中，地址通过计算得出。`lea -0x10(%rbp),%rax`把`rbp-0x10`放进rax，`mov %rax, %rdi`交给rdi；`gets`的第一个参数正是接收地址，所以`rdi`指向哪里，字符就写到哪里。源码中`gets(expression)`接收`expression`，说明这个地址就是expression的首地址。三条合起来得出结论：`expression`首地址是`rbp-0x10`，从此开始往高地址占16字节。
2. 后面都是`0x00`，换行符没有被保存在这里
3. 数组容量指的是用于存放数组的空间总大小，输入字符数是用户实际输入的字符总数，写入字节数是读取用户输入后，实际写入的字节数。本次应该分别是16，3，4.

## 6. Q4：给栈帧中的数据定位

**先理解：** `call` 在转移到被调用函数时，还会把返回后应继续执行的位置压入栈中。函数序言又保存了调用者的 `rbp`。请结合 Q2 的指令效果，推理它们现在分别位于哪里。

在 Q3 输入完成后、尚未离开 `input` 时观察：

```gdb
info registers rsp rbp
x/4gx $buf
x/gx $rbp
x/gx $rbp+8
info frame
disassemble main
```

`x/4gx` 按四个 8 字节单位显示内存。把其中某个值当作地址，需要结合指令和上下文证明。`info frame` 提供 GDB 对当前栈帧的解释，可用于交叉检查；`main` 的反汇编用于寻找调用 `input` 后的那条指令。

| 区域                 | 起始位置（相对 `rbp`） | 字节数 | 内容或用途的依据                                                                        |
| -------------------- | ------------------------ | ------ | --------------------------------------------------------------------------------------- |
| `expression`       | rbp-0x10                 | 16     | `sub $0x10,%rsp`分配，`lea    -0x10(%rbp),%rax` `mov    %rax,%rdi`把该地址交给rdi |
| 保存的调用者 `rbp` | rbp+0                    | 8      | `+0 push %rbp`，`x/gx $rbp`可读到main的帧基址                                       |
| 返回地址             | rbp+8                    | 8      | call压栈，`x/gx $rbp+8`得`0x401ad1`即`main+14`                                    |

1. 哪一处值与 `main` 中 `call input` 后一条指令的地址相符？`rbp+8`那一格，值为`0x401ad1`，与`main` 中 `call input` 后一条指令的地址相符。
2. 按地址从低到高画出以上区域。栈向低地址扩展，与字符串从起始地址向更高地址写入，是否矛盾？

```text
高地址
 0x721000801000  +----------------------------+
                 |  上一层帧的内容            |
 0x721000800ff0  +----------------------------+
                 |  返回地址 0x401ad1         |  8 字节
 0x721000800fe8  +----------------------------+
                 |  保存的 rbp 0x721000800ff0 |  8 字节
 0x721000800fe0  +----------------------------+  <- rbp 指向这里
                 |  expression[0..15]         |  16 字节
                 |  1+2\0                     |
 0x721000800fd0  +----------------------------+  <- rsp
低地址
```

不矛盾，缓冲区内部是从低地址向高地址写；但整个缓冲区/栈帧是通过栈指针向低地址移动腾出来的。

3. 局部数组占用空间与整次调用涉及的栈数据，是同一范围吗？

不是同一范围，前者一般包含于后者，后者一般还包含返回地址、其他局部变量等。

## 7. Q5：观察 `leave` 和 `ret`

使用短输入完成本题。若沿用 Q3 会话，可在输入完成后设置以下断点，再 `continue`；若新开会话，则设置断点后 `run`，并输入 `1+2`。

```gdb
break *input+94
```

停在 `leave` 前后分别观察：

```gdb
x/i $pc
info registers rsp rbp
set $frame_base = $rbp
x/2gx $frame_base
ni
x/i $pc
info registers rsp rbp
x/gx $rsp
ni
x/i $pc
info registers rsp rbp
```

这里保存 `$frame_base`，是因为执行 `leave` 后，`rbp` 的值会变化。请留意每个 `ni` 执行的是哪条指令。

| 时刻                     | `rsp`        | `rbp`        | 下一条指令地址 |
| ------------------------ | -------------- | -------------- | -------------- |
| `leave` 前             | 0x721000800fd0 | 0x721000800fe0 | 0x4019d5       |
| `leave` 后、`ret` 前 | 0x721000800fe8 | 0x721000800ff0 | 0x4019d6       |
| `ret` 后               | 0x721000800ff0 | 0x721000800ff0 | 0x401ad1       |

1. `leave` 的效果能否用 `mov %rbp,%rsp` 再 `pop %rbp` 解释？
2. `ret` 前栈顶的值，与 `ret` 后的执行地址是什么关系？
3. 能否用自己的话解释“返回地址”和“保存的 `rbp`”各自解决什么问题？

**我的回答：**

1. leave前rsp为`0x721000800fd0`, `mov %rbp,%rsp`后，应该为`0x721000800fe0`。而`pop %rbp`，在cpu里是

```asm
mov (%rsp), %rbp
add $8, %rsp
```

前者从$rsp读8字节，放进rbp，也就是`0x0000721000800ff0`，后者使rsp+8变为`0x721000800fe8`，

2. ret前栈顶的值是`0x401ad1`，和ret后的执行地址相同
3. 返回地址解决的是回到`main`的哪一条命令继续，而保存的`rbp`解决的是“main 继续执行时，用哪个值当局部变量的基准，以及它将来返回时把这个值还给谁”。

我的回答：

第一问：
3, 15, 16为一类，退出码0；24为一类，退出码135；100为一类，退出码139.
16的结束`\0`写进保存rbp的那一格，后果不显现。被异常更改的rbp没有被使用，除了eval 里的 mov %eax,-0x4(%rbp)，但写入落在仍然映射的栈上；随后第二次读取遇到 EOF，puts 加 exit(0) 结束进程。

第二问：

确实全部完整保存了`1111111111111111`和最后的`\0`，含`\0`的话共16个字符，17个字节。

input中`char expression[MAXLEN+1];`决定了编译器分配的字节数，不限制`gets`写入多少

eval中`int len = strlen(command_buf) > MAXLEN ? MAXLEN : strlen(command_buf);`计算的是MAXLEN和`str_len(command_buf)`中的较小值。随后的代码将`wrapper_back`写到8+len处，从而覆盖了后续的字符。

第三问：

答案是`N+1`，`+1`是gets自己补充的`\0`

rsp是栈顶指针，往栈中压入数据后，rsp会减小，弹出数据后变大。rbp是栈帧基址指针，函数执行过程中一般不变。缓冲区地址是用于临时存放数据的连续内存区域的起始地址，常表示为rbp或rsp加一个偏移

函数序言要保存调用者的rbp，建立当前函数的栈帧基址，并为局部变量分配栈空间。

leave等价于

```asm
mov %rbp, %rsp
pop %rbp
```

作用是释放局部变量空间，恢复调用者的栈帧基址。

ret弹出一个值到指令指针rip，让cpu返回调用者继续执行
